Q1 Monitored IBAN sequences

HackerPay billing analytics: find IBANs under monitoring with 2+ completed transactions inside any 24-hour window, group them into sequences, and report per-sender sequence lengths and totals.

▤ Problem ▾
Two tables: transactions(dt, sender, amount, completed) and monitor(iban). A completed transaction has completed = 'yes'. Group each monitored sender's completed transactions into time-ordered clusters where consecutive transactions are within 24 hours of each other. Keep clusters of length ≥ 2. Output sender, sequences_lengths, sequences_total, sorted by sequences_total descending.
✓ Solution ▾ 
WITH filtered AS (
  SELECT
    t.sender,
    CAST(t.dt AS DATETIME) AS dt,
    t.amount
  FROM transactions t
  JOIN monitor m ON m.iban = t.sender
  WHERE t.completed = 'yes'
),
ordered AS (
  SELECT
    sender, dt, amount,
    LAG(dt) OVER (PARTITION BY sender ORDER BY dt) AS prev_dt
  FROM filtered
),
flagged AS (
  SELECT
    sender, dt, amount,
    CASE
      WHEN prev_dt IS NULL OR TIMESTAMPDIFF(SECOND, prev_dt, dt) > 24*3600
      THEN 1 ELSE 0
    END AS new_group
  FROM ordered
),
grouped AS (
  SELECT
    sender, dt, amount,
    SUM(new_group) OVER (PARTITION BY sender ORDER BY dt) AS grp
  FROM flagged
),
sequences AS (
  SELECT
    sender, grp,
    COUNT(*) AS seq_len,
    SUM(amount) AS seq_total
  FROM grouped
  GROUP BY sender, grp
  HAVING COUNT(*) >= 2
)
SELECT
  sender,
  GROUP_CONCAT(seq_len ORDER BY seq_len DESC SEPARATOR ',') AS sequences_lengths,
  SUM(seq_total) AS sequences_total
FROM sequences
GROUP BY sender
ORDER BY sequences_total DESC;
◈ Why it works ▾
Gaps & islands

LAG() finds each transaction's predecessor in time; a running SUM() of "gap > 24h" flags turns those flags into stable group IDs — the standard trick for clustering consecutive rows.

JOIN as filter

Joining transactions to monitor on iban = sender does double duty: it restricts to monitored senders and implicitly requires the sender to exist in monitor at all.

HAVING COUNT ≥ 2

Drops singleton clusters after grouping — a lone transaction with no neighbor within 24h doesn't satisfy "two or more."

Verified against sample

AE86...517's 6 transactions split into clusters of 3 and 2 (a lone one is dropped), giving sequences_lengths "3,2" and sequences_total 155.48 — matching the expected output exactly.

Q2 Healthcare record-keeping Spark job

Complete main.job.pipeline.PySparkJob: init a Spark session, filter medical records against eligibility, backfill full names, and compute two aggregates.

▤ Problem ▾
medical.csv holds memberId, fullName, paidAmount (one row per member, fullName starts empty). eligibility.csv holds one eligibility record per member. Implement four methods plus a Spark session initializer:
  • init_spark_session() — local master, app name Data Cleaning
  • filter_medical() — drop medical rows whose memberId isn't in eligibility
  • generate_full_name() — backfill fullName from eligibility's firstName + lastName
  • find_max_paid_member() — memberId with the highest paidAmount
  • find_total_paid_amount() — sum of paidAmount
✓ Solution ▾ 
from pyspark.sql import SparkSession, DataFrame
from pyspark.sql import functions as F


class PySparkJob(PySparkJobInterface):

    def init_spark_session(self) -> SparkSession:
        return SparkSession.builder \
            .master("local") \
            .appName("Data Cleaning") \
            .getOrCreate()

    def filter_medical(self, eligibility: DataFrame, medicals: DataFrame) -> DataFrame:
        # keep only medical rows whose memberId exists in eligibility
        eligible_ids = eligibility.select("memberId").distinct()
        return medicals.join(eligible_ids, on="memberId", how="inner")

    def generate_full_name(self, eligibility: DataFrame, medical: DataFrame) -> DataFrame:
        # fullName in medical is empty -> rebuild from eligibility
        names = eligibility.select(
            "memberId",
            F.concat_ws(" ", F.col("firstName"), F.col("lastName")).alias("computedFullName")
        )
        result = medical.drop("fullName") \
            .join(names, on="memberId", how="left") \
            .withColumnRenamed("computedFullName", "fullName")
        return result

    def find_max_paid_member(self, medicals: DataFrame) -> str:
        row = medicals.orderBy(F.col("paidAmount").desc()).first()
        return row["memberId"]

    def find_total_paid_amount(self, medicals: DataFrame) -> int:
        total = medicals.agg(F.sum("paidAmount")).collect()[0][0]
        return int(total) if total is not None else 0
◈ Why it works ▾
Inner join filters

Joining medicals against a distinct set of eligibility memberIds naturally drops any medical row with no match — no explicit anti-join needed.

Drop before rejoin

The empty fullName column is dropped before the join to avoid a name collision, then rebuilt with concat_ws — which skips nulls, unlike plain concat.

orderBy + first()

Sorting descending by paidAmount and taking the top row is simpler than a groupBy/max for a single "who is the max" lookup.

Null-safe sum

collect()[0][0] can return None on an empty DataFrame — guarding with a ternary avoids a TypeError on int(None).

Q3 timeit decorator

Implement a decorator that measures a function's execution time in milliseconds, logs it, and transparently returns the original result — plus the one-character bug that failed every test case.

▤ Problem ▾
timeit(func) returns a wrapped version of func that: measures elapsed time in ms, appends it to a global list execution_time, and returns exactly what func returned. Candidate functions like delay_max(*args, **kwargs) read their delay from kwargs["delay"].
✓ Solution ▾ 
def timeit(func: Callable) -> Callable:
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        end = time.perf_counter()
        execution_time.append((end - start) * 1000)
        return result
    return wrapper
◈ Why it works ▾
perf_counter over time.time

A monotonic high-resolution clock is the right tool for measuring short durations — it isn't affected by system clock adjustments.

*args, **kwargs pass-through

The wrapper doesn't need to know the wrapped function's signature — it just forwards whatever it received, unchanged, in both directions.

Result captured before return

result is stored, then execution_time.append() runs, then result is returned — so timing never changes the function's actual output.

✕ The bug that broke every test ▾

Traceback pointed to time.sleep(kwargs["delay"] / 1000) raising KeyError: 'delay' — the frame just above it was the real culprit:

result = func(*args, *kwargs)   # single star — bug
result = func(*args, **kwargs)  # double star — fixed

A single * unpacks a dict's keys as extra positional arguments instead of passing them as keywords — so delay never reached kwargs["delay"] inside the wrapped function. One missing character, every test case red.
